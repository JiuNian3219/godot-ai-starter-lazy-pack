# 游戏开发专项规则

## 玩法与手感

- 每个 gameplay 改动都要说明对核心循环的影响。
- 把移动、相机、输入、反馈、伤害、冷却、资源消耗等关键参数做成可调。
- AI 生成代码不能替代试玩，但不要在框架或普通功能阶段追问“好不好玩”。只有用户明确进入垂直切片里程碑时才给正式试玩 checklist；高风险交互可给简短人工功能冒烟检查。
- 临时美术、音效、特效可以用占位，但要标明哪些反馈是占位。

## 性能与资源

- 注意帧率预算、对象数量、资源体积、导入设置和平台差异。
- 不要为了方便把所有东西塞进常驻场景、autoload 或 shared 目录。
- 资源包/分包敏感的内容要遵守 `docs/architecture_rules.md`。

## 场景

- 场景要小而可组合。
- scene script 主要负责协调节点，不承载过多业务逻辑。
- `.tscn` 可以编辑，但要保护资源路径、node name、signal、owner 和外部资源引用。
