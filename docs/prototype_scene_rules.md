# 原型场景规范

原型场景用于快速验证一个机制、交互或调参，不是临时堆放所有未完成内容的地方。

## 放置与命名

- 原型场景放在 `scenes/prototypes/`。
- 文件名使用 `snake_case`，表达要验证的机制，例如 `player_movement_prototype.tscn`。
- 根节点名称表达场景目的，例如 `PlayerMovementPrototype`。

## 范围

1. 一个原型只验证一个主要问题，例如移动参数、塔的目标选择或 UI 焦点导航。
2. 可编辑的关卡布局、碰撞、相机和 UI 结构必须按 `scene_authoring_rules.md` 保存为持久场景节点。
3. 原型可以使用占位资源，但不得把临时代码、自动加载或大型资源依赖带进生产模块。
4. 需要运行时生成的对象要说明生命周期；不要因为原型方便就用运行时节点代替本应可编辑的结构。

## 完成与去向

每个原型在 README、任务记录或场景注释中写明：验证目标、可调参数、运行方式、通过条件和下一步去向。

- 机制进入正式功能后，将可复用脚本和资源移入允许的生产模块，并为关键行为补测试。
- 不再需要的原型删除；不要让它被正式关卡 `preload()` 或主流程依赖。
- 原型不是垂直切片。除非用户明确宣布垂直切片，不要求评价整体乐趣或完成正式试玩。
