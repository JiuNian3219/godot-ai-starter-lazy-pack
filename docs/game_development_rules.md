# 游戏开发专项规范

游戏开发和普通 app 不一样。功能“正确”只是底线，真正的质量还取决于手感、反馈、节奏、资源、帧率、调参效率和试玩循环。

## 0. 阶段门与试玩时机

不要把“能运行”误当成“该评价好不好玩”。当前任务开始前先判断阶段：

- **基础设施**：项目配置、架构、数据形状、场景骨架、工具和自动验证。只做技术验证，不要求试玩或手感结论。
- **普通功能开发**：逐项实现和联调系统。默认做自动验证；只有输入、镜头、节奏或反馈发生高风险变化时，才给一项简短的人工功能冒烟检查，不评价整个游戏是否好玩。
- **垂直切片里程碑**：由用户明确宣布。选取一段可独立体验、能代表最终产品质量的内容；其范围内的核心循环、视觉/UI、声音/反馈、性能基线和关键流程应协同工作。此时才组织正式试玩、观察反馈并调参。

垂直切片不是完整游戏，也不是“有一个按钮能点”的 first playable。它是用有限范围证明质量标准与生产管线可行的高完成度样本。没有用户明确声明进入该里程碑时，AI 不得主动要求“验证游戏好不好玩”。

## 1. 核心循环优先

每个功能都要说明它服务哪个核心循环：

- 玩家做什么？
- 游戏如何反馈？
- 玩家为什么继续？
- 这个功能是否能在第一版 playable 中体现？

如果功能不能服务核心循环，要谨慎加入。

## 2. 手感和反馈

进入垂直切片范围的游戏功能完成后必须考虑：

- 输入响应是否及时。
- 移动、跳跃、转向、攻击、受击是否顺手。
- 是否有声音、动画、粒子、屏幕震动、UI 反馈等必要反馈。
- 是否需要可调参数，而不是硬编码数值。

AI 不能只说“代码完成”；但在普通功能阶段，只需说明是否存在必须人工确认的高风险交互，不要把它扩大成手感或乐趣判定。

## 3. 输入与延迟

输入相关要考虑：

- 键鼠、手柄、触屏是否都需要。
- 输入缓冲、连按、长按、释放时机是否重要。
- 动作游戏要考虑 coyote time、jump buffer、attack cancel、hit stop 等机制是否适用。
- UI 输入和 gameplay 输入是否互相干扰。

## 4. 相机

相机通常是游戏体验核心之一。

需要考虑：

- 跟随速度。
- 提前量。
- 边界限制。
- 镜头抖动。
- 缩放。
- UI 是否遮挡。
- 宽屏/窄屏是否暴露不该看到的区域。

## 5. 动画和状态

动画不是装饰，它经常决定反馈是否清楚。

需要考虑：

- 状态机是否清晰。
- 动画状态和逻辑状态是否同步。
- 是否存在过渡卡死。
- 攻击/受击/死亡是否有明确时序。
- 是否需要 root motion 或纯代码移动。

## 6. 物理与碰撞

Godot 游戏里碰撞层和 mask 很容易后期混乱。

需要考虑：

- 每个物体属于哪个 collision layer。
- 它检测哪些 mask。
- 是 Area2D/3D、CharacterBody、RigidBody 还是 StaticBody。
- 碰撞形状是否和视觉相符。
- 是否需要调试显示碰撞。

改碰撞层、输入映射、物理参数时，要在交接记录里说明。

## 7. 关卡与内容迭代

游戏项目会不断调内容。

需要考虑：

- 测试场景是否足够小。
- 是否有 prototype 场景。
- 关卡资源是否和 gameplay 逻辑解耦。
- 设计师/未来的自己是否能快速调参数。
- 关卡包是否会误引用其他关卡或大资源。

## 8. 资源导入与美术管线

资源不是随便丢进项目就完事。

需要考虑：

- 图片压缩和过滤设置。
- 音频是 stream 还是 sample。
- 模型、贴图、动画的导入设置。
- 像素风是否关闭过滤。
- 大资源是否会进入 shared。
- AI 生成素材是否记录来源和用途。

## 9. 性能预算

游戏有实时帧率要求。

需要考虑：

- 目标 FPS。
- 节点数量。
- `_process` / `_physics_process` 是否过多。
- 是否频繁 instantiate/free。
- 是否频繁加载资源。
- 是否有粒子、灯光、阴影、后处理成本。
- 是否需要对象池或分帧处理。

移动端、Web、低配机器要更保守。

## 10. 调参能力

游戏开发高度依赖调参。

优先使用：

- `@export` 参数。
- Resource 数据。
- 小型调试 UI。
- 测试场景。

避免把手感数值散落在代码里。

## 11. 垂直切片试玩验收

代码验证不等于游戏验收。

只有用户明确进入垂直切片里程碑时，才编写正式人工试玩 checklist：

```text
试玩目标：
操作步骤：
期望手感：
需要观察：
已知问题：
调参项：
```

## 12. AI 完成功能时必须报告

AI 完成游戏功能后必须说明：

1. 核心循环影响。
2. 当前阶段；普通功能仅说明必要的人工功能冒烟检查，垂直切片才给正式试玩计划。
3. 可调参数在哪里。
4. 性能风险。
5. 资源/动画/音效/反馈是否只是占位。
6. 是否需要测试场景或 debug 开关。
